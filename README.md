# Table Talk

Table Talk is the AI sales dining assistant named in `index.html` ("Table Talk - AI Sales Dining Assistant"). The home page says "Break bread. Close deals." and "AI-powered dining recommendations that understand executive preferences and accelerate your sales process."

The screen in `src` is:

- Executive search (`src/components/ExecutiveSearch.tsx`): a "Find Executive" form. The note under the field says "AI-powered search with entity disambiguation and preference inference".
- Profile (`src/components/ExecutiveProfile.tsx`): name, title, company, location, and diet, cuisine, and preference traits, each with a confidence percentage.
- Venue cards (`src/components/VenueCard.tsx`): rank, match score, cuisine, distance, price, noise, rating, feature badges, an AI rationale, and a "Book This Venue" button.

The header says "Table Talk", "AI Sales Dining Assistant", and "Powered by AI". Any search shows the same mock profile in `src/pages/Index.tsx`: Jane Doe, Chief Financial Officer at Atlassian, in San Francisco, CA, with the mark "AI Verified". The traits, with the badge showing confidence times 100 and no decimal, are Pescatarian 92%, Moderate wine 78%, Mediterranean 85%, Japanese 73%, Quiet & Private 88%, Premium ($$$$) 81%, and Low (<65 dB) 76%. A badge is the primary color at 80% or above, the accent color from 60% up to 80%, and muted below 60%. None of these seven traits is below 60%. Moderate wine has type `diet`, so it is listed under "Dietary Restrictions" with Pescatarian, and the label "Alcohol" is not shown. Mediterranean and Japanese are under "Preferred Cuisines". Those four chips show the value only. Quiet & Private, Premium ($$$$), and Low (<65 dB) are under "Preferences", and those cards show the label and the value. The field placeholder is already "e.g., Jane Doe, CFO at Atlassian". The button says "Search". A blank search, including spaces only, does not submit. Any other text is stored and is not used to choose a person. A toast says "Found executive: Jane Doe". A second search hides the Meeting Context form and the venue cards immediately, keeps the profile, and shows the form again after 800ms. The form title is "Meeting Context". Date, time, and location are HTML `required` fields, so an empty one is stopped by the browser before the submit handler runs. That handler still contains the unused messages "Please select a date", "Please select a time", and "Please enter a location". Party size starts at "2 people", and the other choices are "3 people", "4 people", and "5+ people". Budget starts at "Moderate ($$)", and the other choices are "Budget ($)", "Upscale ($$$)", and "Premium ($$$$)". The location placeholder is "e.g., Downtown San Francisco, near HQ". Those values are not used. The submit button says "Generate Recommendations". A complete submit toasts "Generated 3 personalized recommendations". A second search unmounts that form, so when it returns the date, time, and location are empty again, party size is "2 people", and budget is "Moderate ($$)". The rating on each card is drawn beside the same Users icon as Party Size. The 404 page logs `404 Error: User attempted to access non-existent route:` followed by the path. Before a search, the page says "Search for an executive to get started". Any other path shows "404", "Oops! Page not found", and "Return to Home", and logs the path. `App.tsx` mounts both the shadcn toaster and Sonner. The search, recommendation, and booking toasts come from Sonner, so the shadcn toaster stays empty. `QueryClient` is created and no page calls it. The form submit receives `date`, `time`, `partySize`, `location`, and `budget`, and `Index` ignores that object. The stored party sizes are `"2"`, `"3"`, `"4"`, and `"5"`. The stored budgets are `"budget"`, `"moderate"`, `"upscale"`, and `"premium"`. A booking id other than `"1"`, `"2"`, or `"3"` makes the toast title `Booking undefined...`. The three buttons pass those three ids. The commits on 2025-10-13 are from gpt-engineer-app[bot].

From the repository root:

```bash
npm install
npm run dev
```

Vite serves the app. `npm run build` writes the production bundle. The UI uses React, TypeScript, Tailwind CSS, and shadcn-ui.
